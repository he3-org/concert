# AGENTS.md

Guidance for AI coding agents working on the Concert repository. Optimised for low token consumption — read this once per session, then act.

## What Concert is

`@he3-org/concert` is a CLI npm package (TypeScript, built with `tsup`, tested with `vitest`) that installs AI agent definitions and slash commands into target repos. Three commands: `init`, `update`, `push`. Skills and rules are fetched on demand from `he3-org/concert-assets`.

See `.github/copilot-instructions.md` for the full architecture summary. Do not duplicate it here.

## Build, test, typecheck

```bash
npm run build        # tsup
npm test             # vitest run
npx tsc --noEmit     # typecheck only
```

Run only the existing scripts. Do not introduce new linters, formatters, or test runners.

## Where things live

| Path                                  | Purpose                                              |
| ------------------------------------- | ---------------------------------------------------- |
| `src/`                                | TypeScript source                                    |
| `src/commands/`, `src/lib/`           | CLI commands and shared library code                 |
| `src/__tests__/`                      | Vitest tests                                         |
| `templates/`                          | Files copied verbatim into target repos on `init`    |
| `.github/agents/*.agent.md`           | Concert agent definitions (managed, version-stamped) |
| `.github/skills/*/SKILL.md`           | Skills authored in this repo                         |
| `.claude/commands/`, `.claude/rules/` | Claude Code slash commands and rules                 |
| `docs/`                               | Human-facing docs (e.g. `TOKEN-OPTIMIZATION.md`)     |

## Token-optimisation rules (apply to every change)

Full guide: `docs/TOKEN-OPTIMIZATION.md`. The minimum bar:

1. **Bullets and tables, not paragraphs.** Convert prose to lists or two-column tables.
2. **Say it once.** Do not duplicate boilerplate across agents, skills, or instruction files. Reference the canonical location.
3. **Bounded outputs.** Every agent declares the size and shape of its output.
4. **Read by path.** Quote only the lines you need; use `view_range`.
5. **Size targets.** Agents ≤ 250 lines / 12 KB. Skills ≤ 150 lines / 6 KB. Repo-instruction files (this one, `CLAUDE.md`, `copilot-instructions.md`) ≤ 100 lines.
6. **No decoration.** No personas beyond one sentence, no emoji, no banners, no restatement of the user.
7. **Edits must not increase agent file sizes** unless the size cost is clearly justified by behaviour the agent could not otherwise produce.

When authoring or editing:

- New agent → follow `.github/skills/agent-authoring/SKILL.md`.
- New skill → follow `.github/skills/skill-authoring/SKILL.md`.

## Managed-file rules

Concert agent files in `.github/agents/` and template files under `templates/` are version-stamped. Each must contain `AUTO-GENERATED BY CONCERT vX.Y.Z` in the first 15 lines. `cleanupStaleFiles()` (in `src/lib/copy.ts`) deletes files with a stale version. Do not remove the header.

## Change discipline

- Smallest viable change. Do not refactor unrelated code.
- If you add a new path that ships with the package, update `package.json` `files`.
- If you add a new agent, also add the corresponding `.claude/commands/` slash-command file when the existing agents have one.
- Run `npm run build && npm test && npx tsc --noEmit` before declaring done.

## What not to do

- Do not edit other agents' definition files in `.github/agents/` to fix problems unrelated to your task.
- Do not inline content from `docs/` into agents — reference by path.
- Do not add new dependencies without checking the GitHub advisory database first.
- Do not commit secrets, large fixtures, or generated artifacts.
